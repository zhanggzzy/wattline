# Design

## Context

快照中的每台机器已带 `devices`，字段来自 `nvidia-smi` 的 `uuid`、`index`、`name`、`bus_id`；机器配置本身没有型号字段。现状是展开侧栏显示通用两格主机图标、实例名和状态点，收起侧栏同时隐藏名称和通用图标，只保留状态点。应用只有浅色内容区，侧栏是深色背景；没有独立的深色主题实现。

## Goals / Non-Goals

**Goals:**

- 在不改配置、采集和 API 的前提下，用已采集的设备名恢复收起侧栏的机器身份。
- 让四类已确认机型在实际 64px 折叠侧栏中可辨认，未知和歧义情况诚实回退。
- 保留状态、选中、导航、键盘焦点、悬停提示和展开行为。

**Non-Goals:**

- 不新增机器型号配置、数据库字段或后端接口。
- 不按实例名、地址、机器外形或机器名猜测型号。
- 不新增应用主题、彩色图标或按性能排序的新语义。
- 不改变总览图表、详情页或采集行为。

## Decisions

### 1. 以 `devices[].name` 作为唯一可靠型号来源

设备名是 `nvidia-smi` 实际报告的产品名，旧配置只要已有采样就能使用，无需迁移。配置和快照均不增加 `model` 字段，避免维护第二套事实来源。备选方案是按机器名或别名推断，但用户可任意改名，不能作为可靠依据；备选方案是新增型号配置，但会和真实硬件漂移且需要迁移。

分类规则：

| 轮廓 | 匹配的设备名 token |
| --- | --- |
| 厚重机柜 `b300` | `B300` 独立型号词 |
| 双槽卡 `pro6000` | `RTX PRO 6000` 或 `PRO 6000` |
| 紧凑方盒 `spark` | `GB10` 或 `DGX Spark` |
| 双风扇卡 `rtx5090` | `RTX 5090` 或独立的 `5090` 型号词 |
| 通用主机 `generic` | 无设备、型号为空、未知或歧义 |

### 2. 保守的“全机一致”判定

设备清单必须完整可信才参与机型判定：至少有一张设备、每个设备名都非空、清单数量与 `expected_gpu_count`（若配置）一致，且当前在线样本的 `gpu_inventory_complete` 不为 `false`。任一条件不满足即回退 `generic`，但仍保留已知的非空设备名用于提示。对全部设备名去空白、去重后，只有每个名称都能识别为同一类时，才使用该机型轮廓；未知设备名或同类歧义（一个名称命中多个机型词、型号数字越界）同样回退。

离线或过期机器没有当前 `metrics`，此时使用快照中最后保留的 `devices` 清单；只要清单数量与期望一致且名称完整，仍显示最后已知机型，否则回退。备选方案是取多数或第一张卡，但会掩盖不完整清单和异构多卡，本变更优先诚实回退。

### 3. 内联单色 SVG，而不是伪元素拼形状

每个按钮内使用 `<span class="machine-icon" data-model="…">` 包裹 `viewBox="0 0 24 24"` 的内联 SVG，轮廓全部 `fill:none; stroke:currentColor`，仅 Spark 指示点和通用主机的指示灯做小面积实心。好处是缩放和描边在 24px 与 18px 下稳定、只有一种颜色、无额外资源请求，且 `data-model` 可供验证。备选方案是 CSS 伪元素，和现有通用图标一样可行，但四个轮廓的圆角、双风扇和连接金手指需要更多定位代码，且难以在窄尺寸保持一致描边。

通用主机轮廓保留现有“两格机箱”视觉，减少未知机器的识别断层。

### 4. 收起侧栏布局

- 折叠侧栏宽 64px，机器按钮内容宽 48px；轮廓 24×24px，选中态继续使用既有底色和边框。
- 状态点绝对定位在按钮右上角，加 2px 深色描边与轮廓分离；状态颜色和 `title` 不变。
- 展开模式复用同一轮廓，尺寸 18×18px，实例名和状态布局不变。
- 不使用响应式颜色；`currentColor` 在深色侧栏取浅色文字色，在浅色内容区取深蓝文字色。

### 5. 同型号后缀

只为“同一 `data-model` 分组内多于一台”的机器生成后缀。取实例名（无名称时取 id）末尾 2–4 个字形（grapheme），选择能让组内唯一的最短长度；仍相同则使用组内序号。按字形而非 UTF-16 码元截取，代理对、组合字符和 emoji 序列不会被截断。后缀放在轮廓下方，`aria-hidden`，完整实例名和型号仍在按钮的 `aria-label`、`title` 与键盘聚焦提示中。备选方案是始终显示后缀，但四类轮廓不同时无需增加视觉噪音。

分组按轮廓类别而非完整设备名：同是 B300 的不同 SKU 也属于同一轮廓，需要后缀区分。

### 6. 可访问名称与提示

按钮的 `aria-label` 和 `title` 由实例名、状态、去重后的完整设备名依次组成，未知但可读的设备名也保留，只有完全没有设备名时不追加型号段。当两台机器的这组身份文本完全相同时，再追加 `实例 {后缀}`（英文 `instance {后缀}`），保证同名实例的可访问名称和提示也能区分。状态点只负责视觉状态且 `aria-hidden`，不再携带独立 `title`，因此悬停按钮任意位置都命中按钮的完整身份提示。键盘聚焦提示继续使用现有 `::after { content: attr(title) }`。模式不影响可访问名称。

### 7. 渲染签名包含全部机器的机型派生值

现有页面只在渲染签名变化时重绘，而签名原先只覆盖选中机器的设备。侧栏、总览和后缀分组依赖全部机器的机型，因此签名对每台机器加入识别结果 `kind` 与去重后的完整设备名。轮询仅更新任一机器（包括未选中机器）的型号时也会重绘轮廓、提示和后缀，不依赖导航触发。

## Risks / Trade-offs

- [nvidia-smi 的新命名变体不在匹配表] → 未识别时回退通用轮廓，并在提示中显示真实设备名；后续只需扩展匹配表，不改数据契约。
- [异构多卡机器被回退为通用轮廓] → 这是有意的保守行为，避免把整机误标成某一类；提示仍列出全部设备名。
- [极长或完全相同的实例名导致后缀不理想] → 后缀最长 4 字符并省略溢出，完全相同名称使用组内序号。
- [64px 侧栏空间有限] → 轮廓固定 24px、状态点绝对定位、后缀 9px；在 320/390/1440 宽度核验无横向溢出。
- [没有应用级深色主题] → 不伪造主题；用 `currentColor` 验证深色侧栏和浅色内容区两种实际背景，并检查纯单色渲染。
- [逻辑只在浏览器端，缺少独立单元测试框架] → 在合成浏览器检查中直接调用机型映射函数并覆盖全部矩阵，再断言实际 DOM、尺寸、状态和截图。

## Migration Plan

无数据迁移。部署仅替换前端静态资源；回滚为还原 `monitor.js` 与 `monitor.css`。旧机器不需要重新登记，未知型号在首次采样前显示通用轮廓。
