# Design

## Context

`Monitor.metrics_from` 已把宿主 `MemTotal - MemAvailable` 归一化为 `memory.used_bytes`，容器样本直接提供 cgroup `memory.current`；`memory_percent` 由同一 `used_bytes` 计算。服务端公开快照不裁剪内存对象，历史也已记录 `memory_used`。因此本变更无需后端或 API 改动，仅补齐总览展示。

前端 `monitor.js` 的 `drawRows()` 只负责重建结构，`paint()` 每两秒按 `[data-value]` 更新数值。总览内存格当前只有百分比字段和百分比 meter；详情卡的辅助文本已含 `used / total GiB`，但已用量未逐项带单位。浏览器合成检查以 48 GiB / 128 GiB、38% 的内存样本覆盖布局与语言流程。

## Goals / Non-Goals

**Goals:**
- 总览内存列在百分比旁显示实际已用 GiB，并随 `paint()` 刷新。
- 详情卡把已用量与总量都写成带 `GiB` 的数值，保留“已用”/容器含缓存语义。
- 缺失、过期、离线与无上限容器沿用既有占位和口径，不产生 0 GiB 假象。
- 不改变历史图表的指标集合或后端数据流。

**Non-Goals:**
- 不新增内存历史序列、图例或图表指标按钮；图表仍展示使用率，无上限容器继续展示已用量。
- 不修改采样口径、`used_bytes` 推导规则、API schema 或历史归档。
- 不新增语言、单位制或用户配置项。

## Decisions

1. **复用快照 `memory.used_bytes`，不做二次估算。** 服务端已给出唯一口径；前端只在值缺失时显示占位符。备选：前端用 `total - available` 推算。放弃，因为会绕过服务端口径并在容器/宿主间产生不一致。
2. **总览使用同一单元格内的次要行，不新增表格列。** 在百分比下追加 `<small class="memory-used">`，内容为 `GiB` 数值加现有 `used` 文案；`paint()` 同时写主值和已用量，值缺失时隐藏次要行。备选：新增“已用内存”列。放弃，窄屏和现有六列宽度会拥挤，且需求强调并列而非独立列。
3. **详情卡保留百分比为主读数，辅助文本显式标注两次 `GiB`。** 即 `48.0 GiB / 128.0 GiB 已用`，避免单位只覆盖总量。无上限容器仍以已用量为主读数，不重复辅助数值。
4. **已用量使用 `gib()` 与 `fmt(...,' GiB',1)`。** 与 GPU 显存和系统盘一致，采用 1024 幂和一位小数，沿用 `Intl` 本地化数字格式。

## Risks / Trade-offs

- [总览行高或宽度增加导致窄屏溢出] → 次要行使用小号 muted 文本，复用容器查询的卡片布局；在浏览器检查中覆盖 320–1440 宽度。
- [两秒刷新时结构未重建导致已用量停留在旧值] → 已用量作为 `[data-value]` 字段由 `paint()` 更新；结构只在形状变化时重建。
- [旧快照缺少 `used_bytes`] → 主百分比仍显示，已用量显示并随后隐藏占位；不会渲染 0。
- [容器无上限时主值与副值重复] → 该分支主读数即 GiB，副值置空并隐藏。
