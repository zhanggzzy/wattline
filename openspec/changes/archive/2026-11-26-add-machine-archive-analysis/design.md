# Design

## Context

日维护在现有归档锁内发布 v1 gzip JSONL 并更新 `cold_archives`。单节点移除也持有该锁，按稳定身份改写归档。近期趋势已经定义了整机指标、采样降采样和断线语义。用户需求见 AN-220，实施阶段为 AN-222。

## Goals / Non-Goals

查询已发布的整机冷归档，沿用近期趋势的绘图、键盘和数据表交互。逐卡归档分析、冷热趋势合并和实例部署在本次范围之外。

## Decisions

- 由已登记机器的稳定历史身份定位作业。POST 启动或复用作业，GET 查询状态及趋势。只使用归档索引中已提交的文件，避免把中断导出的残留文件当作已归档数据。gzip 文件共享时仍需扫描完整流并验证结尾，仅将匹配机器的整机指标写入按时间索引的 SQLite 临时数据库。
- 解压与移除、压缩通过现有归档锁串行，样本暂存和读图在工作线程执行。进度按已读取的压缩字节占总量计算，解压校验和暂存都完成后显示 100%。页面轮询作业，空或失败状态允许返回或重试。
- 起止日期默认覆盖该机全部归档样本，以配置的归档时区解释为区间起始日零点至结束日次日零点。图表时间标签也使用该时区。后端复用现有断线和降采样逻辑，并限制绘图点数量。
- 临时 SQLite 工作空间由当前进程独占，无持久目录或迁移。正常完成后保留 15 分钟空闲时间，读图刷新期限。失败或无样本立即关闭工作空间。移除机器时使作业失效，退出时收尾并关闭。正在读取时延后释放。Unix 上 SQLite 临时数据库采用删除式打开，进程异常退出由操作系统回收句柄。此方案无需额外定时服务或接入每日压缩清理。

## Risks / Trade-offs

- 共享归档的首次打开需要扫描全部已发布文件。一次只解压一个作业，避免磁盘并发放大。长扫描期间，日维护和节点归档移除需等待归档锁。
- 输出按时间分桶，长日期范围会聚合样本。缩小范围可提高图表时间分辨率。分析结果在空闲过期后重新打开会重建。

## Migration Plan

新旧程序共用现有配置、SQLite 主库 schema 和 gzip 文件。此功能引入的临时库随进程或作业结束回收。
