## Context

The reviewed AN-202 patch stores tolerance overrides in machine settings JSON and sends a numeric threshold to the standalone Linux probe. A room is a physical assignment, and cluster links allow many-to-many membership across rooms. This change extends those contracts while keeping the probe and enrollment routes.

## Decisions

1. Resolve each field independently using the machine's stable registry record and current room and cluster links. A numeric stored machine value takes precedence over a numeric machine-file value. An absent stored field preserves the file value. An explicit stored null clears this level, including an explicit file value, so operators can restore inheritance without editing the file. Absent file values and historical implicit registration zero inherit. A saved numeric settings value of zero always overrides. Other machine settings and registration payloads retain their existing meanings.
2. Consider explicit member-cluster overrides for this field. A unique value wins, with all contributing clusters reported if they agree. Distinct values require an explicitly selected member cluster that sets this field. Without a usable selection, surface the conflict and fall back to the machine's room and then global. Keep a stale selection identifiable and clearable. A machine override wins even while a lower-tier conflict exists. A room's own baseline inherits global. A cluster without a local value has no singular baseline, so show applicable member-effective values and sources.
3. Keep machine values and source selections in the existing machine settings transaction, including alias and room changes. Keep group thresholds in the respective group rows and write them with group attributes or membership in the same transaction. Old clients can omit new fields. Global has one nullable override, with the product default of 256 MiB below it. Publish committed settings to memory before reporting success. Failed writes leave the prior state in effect.
4. Resolve the effective policy immediately before sampling, after acquiring the collector slot. Pass an immutable machine copy with the numeric threshold to the existing collector. Expose the policy captured by any displayed sample alongside current configuration, so a sample that was already running may finish with its original threshold. The next sample uses the values and links then committed.
5. Reuse the native machine and group detail dialogs. Keep separate saves for the assignment editor and group/machine deletion confirmation, so each action has a defined transaction. Machine properties, monitoring, room placement, cluster-source selection and assignment are available within Configure. Group settings contain their existing name, location or members, and owner or user fields. Overview opens a localized global policy form. Storage keeps its existing operations and does not use the Linux policy.
6. AN-215 landed on main during implementation. Keep its collection validity rules. A valid sample with unconfirmed GPU occupancy reports the per-card state and applicable diagnostics, while collection events follow the sample validity window. Reuse the prior patch's count verification, PID precedence and idle threshold without reintroducing the removed aggregate warning.

## Migration Plan

Replay the reviewed four-commit patch on the fetched main when the GPU tolerance change is absent. Apply an additive SQLite migration for room, cluster and global policy. Load legacy machine JSON in place, distinguishing old registration defaults, omitted settings and explicit saved overrides. Future rollback to a schema-10 binary requires a consistent pre-upgrade backup. Use synthetic data for local delivery.
